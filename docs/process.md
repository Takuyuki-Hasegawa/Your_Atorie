# 進め方

最終更新: 2026-08-27

思想の正は [philosophy.md](./philosophy.md)。画面の中身は [product-spec.md](./product-spec.md)。データの置き場は [architecture.md](./architecture.md) の「保存の計画」。このファイルは、**いま何を確認していて、次に何をするか**。

## 入力と出力

やることは二つだけ。混ぜない。

```
入力 = 作成画面。カードを書く
出力 = 受け手画面。渡したあとに相手が見るもの
```

入力はPCでやる。出力の確認先だけ、段階を追って変える。

## 段階

いまは **④**。

| | 何をする | 入力 | 出力の確認 |
| --- | --- | --- | --- |
| ① | PC上で確認 | PC | PC |
| ② | スマホ上で確認 | PCのまま | 同じWi-Fiのスマホ |
| ③ | web上にリリース | PC | 公開URL。まだ自分の端末 |
| **④** | **QRで他人が読める** | **PC** | **会っている相手の端末** |
| ⑤ | QRの先が②と同じ | 同じ | ④で見えた画面が、②で触った出力と同じ |

アカウント・友達・Bluetooth は⑤のあと。

## ④ のやり方（QRで渡す）

写真や文章があるのは、いままで書いてきた **そのブラウザの箱**。公開URLを開いただけでは空に見える。空なのは消えたのではなく、別の箱を見ている。

渡すときは、その箱から `trips/{id}.json` と写真を GitHub Pages に置き、QRを画面に出す。QRの先は:

```
https://takuyuki-hasegawa.github.io/Your_Atorie/?c={id}
```

### 1. このコードが Pages に載っていること

`main` へ push してある。Actions が終わっている。③のアプリ本体に、④の読み取り（`?c=`）が入っている状態。

### 2. PCで箱の窓口を起動する

リポジトリのフォルダで:

```powershell
node server.mjs
```

この窓は閉じない。`渡す` はここへ POST する。HTTPSの公開ページから localhost へは届かない。

### 3. データがあるタブで「渡す」

**写真や文章が見えているPCのタブ**で作成画面を開く。

- ①を `file:///C:/Users/takuy/code/Your_Atorie/index.html` で書いていたなら、**その同じURL**（末尾 `#create`）
- 公開URLや空の 4180 を新規に開いただけでは、①の下書きは乗っていない

作成画面の **渡す** を押す。QRが出る。

- 「node server.mjs を起動してください」→ 2 が動いていない
- QRが出た → カードはディスクに置かれた。`git push` まで行けば Pages に載る

`渡す` は `trips/` と `media/` だけを commit して push する。Pages の更新に一分かかることがある。すぐ読むと「まだ届いていません」になる。

### 4. 会っている相手がQRを読む

相手のカメラで、PCに出ているQRを読む。チャットにURLを貼るためのものではない。

相手の画面は表紙 → 手札 → 開く。作成ボタンは出ない。

### うまくいかないとき

| 症状 | 原因 |
| --- | --- |
| 公開URLが空 | ③の箱。まだ `?c=` が付いていない。3 のタブで「渡す」する |
| QRを読んでも空／届いていない | Pages がまだ更新中。一分待って開き直す。または 3 が別タブだった |
| 「node server.mjs を起動してください」 | 2 が動いていない。起動し直して、データが見えるタブでもう一度 |

LANのコピー機（②）は手元確認用に残してある。作り方は下の「② のやり方」。

## ③ のやり方（公開URLでアプリを開く）

置くのはアプリのファイル。確認するのは「自分のスマホで、HTTPSのURLから画面が開く」まで。カード一式は④で乗る。

公開URL:

```
https://takuyuki-hasegawa.github.io/Your_Atorie/
```

1. `main` に push する。GitHub Actions が Pages へ置く
2. リポジトリが **public** であること（private の無料枠では Pages が使えない）
3. 自分のスマホのブラウザで、上のURLを開く

このURLの箱は、`file://` とも `127.0.0.1:4180` とも別物。

## ② のやり方（同じWi-Fiのスマホ）

スマホで入力し直さない。PCで書いた受け手画面を、同じWi-Fiのスマホで触る。他人には届かない。

PCとスマホを **同じWi-Fi** にする。

### 1. PCでコピー機を起動する

リポジトリのフォルダで:

```powershell
node server.mjs
```

ターミナルに二行出る。

```
PC     http://127.0.0.1:4180/
phone  http://192.168.x.x:4180/
```

`phone` の数字はWi-Fiによって変わる。毎回、今出たURLを使う。この窓は閉じない。

### 2. データがあるタブで「スマホへ」

**写真や文章が見えているPCのタブ**で作成画面を開く。

- ①を `file:///C:/Users/takuy/code/Your_Atorie/index.html` で書いていたなら、**その同じURL**（末尾 `#create`）
- `http://127.0.0.1:4180/#create` を新規に開いただけでは、①の下書きは乗っていない。空に見えるのは別の箱を見ている

作成画面の **スマホへ** を押す。

- 「スマホを更新してください」→ コピーできた
- 「node server.mjs を起動してください」→ 1 が動いていない。起動し直して、もう一度「スマホへ」

### 3. スマホで `phone` のURLを開く

スマホのブラウザに、ターミナルの **`phone` の行** を入れる（例 `http://192.168.40.77:4180/`）。

- PC用の `127.0.0.1` はスマホでは開かない
- すでに開いていたら更新する。コードを直したあとも更新する
- 表紙 → 手札 → 開く、が出力。ここで触る

### うまくいかないとき

| 症状 | 原因 |
| --- | --- |
| PCの 4180 が空 | ①の本体は `file://` 側。4180 は別箱。2 のタブで「スマホへ」する |
| スマホがページを開けない | 別Wi-Fi、または `phone` のIPが古い。サーバーを起動し直して、今の `phone` を入れる。Windows のファイアウォールが 4180 を拒んでいることもある |
| 写真が乗らない | 空のタブで「スマホへ」した。データが見えるタブでもう一度 |

## やらないこと（いま）

- ⑤の前に画面を作り直さない。QRの先は②と同じ出力である
- 入力用のアカウントを作らない
- スマホ用に入力画面を作り直さない
