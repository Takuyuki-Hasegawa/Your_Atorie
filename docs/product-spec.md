## いまあるもの

中国旅のカード。全部カード。一枚か束か。ブラウザ内の下書き。

```
表紙のカード → 手札でトピックを選ぶ → 手札でカードを選ぶ → 開いて読む
```

- 表紙は渡す一枚。重ねた写真カード。押すと手札へ
- トピックも中のカードも、後ろにカードが重なった手札。手前の大きなカードにタイトルとコメント
- 見えている裏のカードを押すと、それが手前に来る。手前のカードを押すと選ぶ。手でずらしてもめくれる
- 下に払うと一段戻る。写真カードは写真のところから。文章カードは先頭まで戻してから下へ
- 開いた写真カードは上に全体が見える。文章はそのすぐ下。枠の光で画面と分ける
- 開いたあとはその一枚だけ。他のカードへは手札に戻って選ぶ。動画は再生ボタンで音付き再生
- 食 / 観光 / 文化・人 — 束。中のカードを手札で選ぶ
- 旅で感じたこと — 一枚ならそのカード一枚。中に足すと束になる

### カードのパターン

- 写真カード: 写真または動画と、タイトルと文章
- 文章カード: 写真なし。羊皮紙の地に文章。開いてスワイプ／見る
- 束: 中にカードが並ぶ。入れ子は一段まで

いいねと、作成者にだけ届くコメントは構想にあるが、渡す（QR）より後。

### 作成

`/#create` で書いて、プレビューして、受け手画面を見る。一枚のカードに文章や写真を入れられる。中にカードを足すと束になる。下書きはこのブラウザに残る。アプリの開き方は [process.md](./process.md) の「③ のやり方」。いまの「公開する」は同じブラウザ用リンクをコピーするだけで、他人の端末には届かない。

PCでは下に払って戻る。矢印キーは手札をめくる。

## 次の一歩（まだ未実装）

```
作成する → そのカードのQRを画面に出す
```

会っている相手が、カメラでQRを読む。リンクをチャットに貼って遠隔送信するのが主目的ではない。

これが成立するには、QRの先で他人の端末からカードが見える必要がある。同じブラウザの下書きでは足りない。アカウント、友達、Bluetooth はこの一歩のあと。

## その先

優先はこの順。

1. 作成 → QRで渡す（他人の端末で見える）
2. 人（アカウント）とカードの紐づき
3. 友達登録している人への通知
4. その場で近づける渡し方（Bluetooth など）
5. カードへのいいね、作成者にだけ届くコメント

## デザイン原則

- 受け手はマッチングアプリのカード。暗い画面、重ねた表紙、写真の上に名前
- 選ぶときは手札。見えているカードを押す。一方向にずらして重ねる。円に広げない
- 戻るときは下に払う。左上の ← は残す
- 作成画面は紙とインクのまま
- 説明文を足して分かりやすくしない。要素を減らす
- 作るより、渡す瞬間が目立つ
